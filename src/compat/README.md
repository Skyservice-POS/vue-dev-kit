# Шар сумісності з BootstrapVue

Мета цього шару — **зняти залежність від `bootstrap-vue`**, а не запропонувати
кращий API. Це принципова відмінність від `src/vue2/`, і від неї залежить усе інше.

## Навіщо

BootstrapVue не має версії під Vue 3 і не матиме. Поки він у залежностях,
`@vue/compat` неможливий, а отже неможливий і Vue 3: compat-білд гасить
депрекації самого Vue, але BootstrapVue лізе у внутрішні API Vue 2 і під ним
не працює.

Тому послідовність така:

1. закрити компонентами цього шару всі `b-*`, які використовує адмінка;
2. зареєструвати їх глобально замість BootstrapVue;
3. викинути `bootstrap-vue` із залежностей;
4. увімкнути `@vue/compat` і йти на Vue 3.

## Чим це не є

`src/vue2/` — **адаптери**: вони обгортають `b-*` і дають наш власний контракт
(`SkyButton`, `SkyInput`…). Для зняття залежності вони не годяться, бо самі від
неї залежать. Їхня задача інша — переводити місця виклику на API дизайн-системи.

`src/compat/` — **реалізації**: вони замінюють `b-*` собою, повторюючи контракт
повністю. Місця виклику не змінюються взагалі.

## Використання

```js
import Vue from 'vue';
import { BootstrapCompat } from '@skyservice-developers/vue-dev-kit/compat';

Vue.use(BootstrapCompat);
```

Після цього `import BootstrapVue from 'bootstrap-vue'` та `Vue.use(BootstrapVue)`
прибираються. Розмітка й поведінка не змінюються — у цьому й суть.

Збірка `compat` **не має жодної зовнішньої залежності**, крім самого Vue.

## Критерій готовності компонента

Не «схоже», а **посимвольний збіг розмітки з оригіналом**. Кожен компонент
має A/B-тест, який рендерить нашу реалізацію і справжній `b-*` із BootstrapVue
на одній матриці пропів і порівнює нормалізований DOM. BootstrapVue підключений
для цього як `devDependency` і в зібраний пакет не потрапляє.

Матриця має покривати всі гілки оригіналу, а не типові виклики: у кнопці це
режими посилання, перемикача й нестандартного тега, які в адмінці майже не
вживаються, але входять у контракт.

Дрібниці відтворюємо теж. Наприклад, у режимі посилання BootstrapVue виводить
клас `disabled` двічі — тест на це впіймав, і ми повторюємо як є: мета шару в
тому, щоб різниці не було взагалі.

## Умова видалення

Цей шар живе стільки, скільки адмінка лишається на Vue 2 з bootstrap-розміткою.
Коли вона перейде на Vue 3 і на власну дизайн-систему, шар знімається разом із
`src/vue2/`. До того — режим підтримки: нових можливостей не додаємо, лише те,
чого бракує для повного покриття `b-*`.
